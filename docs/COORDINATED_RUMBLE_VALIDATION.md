# 协同振动验证：原神攀爬触击

## 2026-11 最终集成

主机使用 SDK #8 的观测/判定/持续层分解及弱击召回修复；客户端保留下述连续原生
输出修复，并给粗略频率提示增加独立的 40 ms 平滑。RichTap 换频在上一段 20 ms
频率曲线完成后采用最新目标，幅度更新及新短点不等候此频率过渡。停止会重置状态。
这一处理减少噪声提示引发的重复换频，但不保证 SoundPool 素材替换具有相位连续性。

原生协同策略只作用于 IR 的双幅度 rumble 近似路由；真实控制器 PCM 波形另走独立
通道。它没有依据手柄品牌猜测频响，也没有将普通 HOST rumble 归零。
最终来源、验证命令及限制见 [离线集成记录](../tools/haptics-offline/README.md)。

## 2026-11 连续原生输出修复（集成前候选）

持续层保留低/高频 RMS 和既有过零率提供的频率提示，传到原生后端；RichTap 使用
连续频率曲线，SoundPool 使用 100/160/260 Hz 的有限素材库。两者的短点背景保护
缩到 12 ms，移除 RichTap 的长期背景压制。短点波形与线性强度映射保持。

未经标定的双转子在原生协同下不再接管 authored 持续层，机身接收完整连续纹理。
独立 HOST rumble 仍可驱动手柄；单输出和原生不可用时保持回退。这替代下方历史
候选的平方振幅分配公式，不是跨设备能量守恒或转子频响校准。

本轮 1328 项 JVM、11 项 SDK CTest 通过，完成 91 + 61 段 PCM 和 120 段压力回归。
主语料雨滴 225/225、攀爬 72/72，在两个后端均保留；纯连续跑步与扫频抽刀无短点。
带噪跑步/抽刀仍有 214/243 个主机误报，未声称消除。未运行 E2E 或真机验证。
完整参数、不同种子结果、已知限制和复现命令见 [离线记录](../tools/haptics-offline/README.md)。

## 2026-11 三阶段重构（上轮主机候选）

主机现在将输入观测、候选判定和持续层分解分开；候选状态与持续层输出不再参与
观测历史或触击强度基线的计算。局部形状需要“整体短时能量隆起”或“稳定背景中的
独立局部突起”佐证，修复上一轮用整体能量一票否决导致的弱触击召回退化。

120 段压力 PCM 已以 240/137 两种块尺寸复测；其中 96 个纯音背景组合，相对原始
SDK 基线均没有召回下降或额外事件增加。85 Hz 背景下，100/160/330 Hz 触击命中从
上一候选的 25/31/54 恢复至基线 28/40/60（每组标注 60）。原 91 段的雨滴 225/225、
攀爬 72/72、背景弱触击 70/72 保持；高频跑步和拍频零误点、带噪跑步 214 个误点
保持，带噪抽刀由 239 增至 243，仍低于原始 427。新增漏检已修复，原有漏检仍存在。

11 项 SDK CTest 和本轮 16 项 Android 定向 JVM 测试通过，61 段不同种子负例/正例
回归也通过。本轮没有继续修改客户端分配曲线，亦未做 E2E 或真机验证。主机需要
重新集成 SDK。详见 [离线实验当前状态](../tools/haptics-offline/README.md#上轮主机三阶段重构与召回修复)。

## 2026-11 连续纹理优化（重构前历史候选）

**新增压力测试已发现召回退化：** 换用 100/160/330 Hz 触击后，部分干净背景正例
比基线多漏检；原生机身持续增益的变化量也可能增大。下面的原语料通过结论不代表
通用保真通过。详见离线实验文档的“后续推演”，应先修复召回再继续强化抑制。

主机 SDK 已加入实测背景能量对照及频谱内区间判据，客户端原生协同分配改用平滑
权重，替代下面首轮的开平方残差公式。91 段相同 PCM：高频跑步误触击 2605→0、
带噪跑步 1549→214、带噪抽刀 427→239；雨滴 225/225、攀爬 72/72 保留，背景弱触击
仍为 70/72。另有 61 段随机种子验证。SDK 11 项 CTest 和 Android 1320 项 JVM 测试
通过，未做 E2E；需要主机集成新 SDK 后才会改变主机事件识别。

重点场景转子指令总变化量下降，但低频主体及背景触击存在小幅增加，不声称所有
输入都更平顺。参数依据、公式、可复现命令、完整计数及限制见
[离线 PCM 实验第二轮](../tools/haptics-offline/README.md#第二轮连续纹理识别与平顺分配)。
没有真实游戏 PCM 或执行器测量，当前结论仍限于离线软件行为。

## 2026-11 原生 DS5 模拟收敛（首轮历史方案）

**离线实验补充（2026-11-07）：本节方案尚不能视为通过保真验证。**
随后生成的 91 段 PCM 表明，客户端减弱力度没有减少 RichTap 的连续纹理误触发；
频带分配在拍频和带噪抽刀样本中还增加了低频指令总变化量。
完整构造方法、数据和局限见 [离线 PCM 实验](../tools/haptics-offline/README.md)。
以下保留第一轮修改及其原有单测范围，不能用软件计数通过替代后续反例结果。

新增对照反馈：影之刃零，外接号称非对称大转子的普通手柄，开启协同和实验性原生
振动。真实 DS5 的跑步是轻微连绵碎振，模拟端有明显大转子摇摆；抽刀的连续嗡振
变化被模拟成短点。此前雨滴和原神攀爬的正例不能证明其他场景没有失真。

本次修改仅作用于增强 IR 的原生机身路径（SoundPool / RichTap）：

- 事件强度是线性局部峰值。移除原生输出的开平方增强，改为
  `point = strength / 0.09 * 0.6 * userGain`。保留原来 100% 用户强度下的
  后端满量程位置：`2 * sqrt(0.09) = 0.6`。例如源值 0.009 的原生参数由约
  0.190 变为 0.060，0.09 仍为 0.6。没有新增最低力度、事件频率限制或场景名称判断。
  这些是兼容渲染单位，不是 DS5 物理振动力的标定。
- 协同模式原来让机身持续层恒为零，现在让原生后端保留连续纹理。以源 RMS
  低、高频幅度 `L/H` 表示，手柄得到 `sqrt(max(L²-H², 0))` 的低频，原生机身
  得到 `min(L,H)` 的低频和完整的高频。低频平方幅度在分配前后相等，高频只分配
  一次；高频占优的细纹理不再额外驱动粗糙转子，明显低频主体仍交给手柄。
  这是保守分配启发式，不是物理能量守恒或已测得的 ERM 频响补偿。
- 仅机身、仅手柄、缺少/关闭原生机身、机身强度为零、普通 HOST rumble、扳机及
  真 DS5 的原始 PCM 通路沿用原有行为。普通转子/固定 TICK 回退没有同步重调。

软件回归覆盖生产协调器、时间线、混合器、机身 worker 和 RichTap 封包：

- 现有主机生成的合成雨景 144 个事件仍全部输出为有强弱区别的 RichTap 短事件；
  80 点/秒的离散脉冲不被新增限频截断，短事件仍使用原生 transient 形状。
- 合成持续层弱→强→弱使用一个 RichTap 持续载波和增益更新，不生成短点；高频
  占优的连续纹理不驱动手柄大转子。低频占优、断连/重连、静音和多人输出另有回归。
- 分配测试验证低频平方幅度、高频归属和单输出回退；测试不证明跨设备物理力感一致。

已知边界：没有影之刃零跑步/抽刀的实际 PCM/IR 录制，也没有本轮实机 DS5 A/B。
现有雨景文件是合成信号，不能标为游戏录制；攀爬手感仍需重复原实机路线。
SoundPool 的 8 档短点量化仍会舍去极弱事件：现有雨景的 144 个源事件中，有 4 个
在新映射下低于首档舍入边界；RichTap 同一文件保留 144 个。没有为补足计数强行抬升
这些弱点。两种后端都需要复测雨滴轻重、攀爬清脆度、跑步连贯性和抽刀连续包络。

主机 SDK 的短点检测没有在本轮修改。对其 445eaa8 版本的探索发现，平滑单音变频
不一定触发短点，但叠加噪声的平滑包络可以产生多个事件；提高回落证据要求又可能
损失密集脉冲。因此本次先修复客户端的强度夸张和持续层分配，不声称消除了主机误检。
如果实机仍有多余短点，应同步录制游戏触觉 PCM、IR 事件及最终后端调用，定位事件
是否已由主机产生。普通 HOST rumble 与 IR 仍独立混合；若大转子来自 HOST，需另查
主机来源，不能仅凭本次 IR 分配改动宣称解决。

参考依据：

- [Bernard 等：The high/low frequency balance drives the perception of noisy vibrations](https://arxiv.org/abs/2311.10644)：
  对纹理振动的感知实验说明高低频平衡对保真有影响。本次据此保留连续纹理的信息，
  具体分配公式是工程启发式，不是论文给出的控制器映射。
- [Android haptics design principles](https://developer.android.com/develop/ui/views/haptics/haptics-principles)：
  区分离散清脆反馈与丰富纹理，并建议频繁触觉保持细微。这支持克制增强的方向，
  不提供 DS5 与手机/转子手柄的幅度换算。

## 三模块边界

生产链为 `GameRumblePipeline` 串联以下三层，Android 协调器只接入设备发现、线程、
偏好与传输；原生 DS PCM 和扳机通道继续独立。

1. `RumbleSignalTracker`：按主机流维护电平、因果包络与正向残差。`sample` 接收主机
   输入，`advance` 仅推进时间；重复电平、ticker 与重连回放保持因果积分。TEST 不进入
   HOST 历史。信号对象统一携带电平及可选分解，不再另外传递一份电平。
2. `GameRumbleAllocator`：唯一入口 `allocate` 把信号和可用输出能力变成两端计划，
   并返回是否需要继续推进；Pipeline 不重复判断分配策略。当前兼容增益集中
   在分配器：机身低通道瞬态 0.25、高通道瞬态 1、高通道持续 0.30，手柄保留 HOST。
   这些是折叠前增益，不代表物理能量比例，也不把支持 CLICK 等同于能可靠接管瞬态。
3. `RumbleOutputRenderer`：执行计划，负责来源混合、输出槽限频、去重与单马达折叠；
   真实 `DeviceVibrationCoordinator` 继续负责强度缩放、幅度裁剪、租约及音频/触摸占用。

本轮是结构重构，未重新启用实测无改善的“机身仅瞬态”方案，也未启用新的原语接管。
未来校准后的分工应修改分配策略和相应渲染后端，无需按游戏场景添加判断。

`GameRumblePipelineTest` 直接使用生产管线、渲染器与真实机身 worker，注入时钟、
调度队列和最终输出回调。覆盖收敛、重复脉冲、过期脉冲、多人隔离、TEST 插入、重连、
音频占用恢复与停止。该组测试将 worker 普通电平间隔设为 0，以隔离线程实际等待；
250ms 冷却和抢占仍由现有 `DeviceVibrationCoordinatorTest` 单独验证。

## 弱幅度保真

机身游戏来源不再使用固定 16 档量化、12 阈值滞回或非零最小值 16。
折叠后的幅度只按用户强度缩放、取整并裁剪到 0–255；相同数值不再因历史电平不同而
输出不同幅度。来源仍取最大值，完全相同的命令仍去重；普通电平写入保留 250ms
间隔、最新值替换和起停抢占。该修改覆盖协同、仅机身与旧机身叠加来源，不改变手柄输出。

新增 worker 回归使用默认 250ms 间隔，验证 1、8、9、21 等弱幅度和双向变化最终按值输出，
验证强度缩放、零停止；管线回归验证高通道 0.1 起振输出 8、收敛输出 2。
这保证数值不被人为抬高，不保证所有设备都能感知最低幅度，也没有解决非零衰减等待冷却。
真机需要另测小幅抖动下的服务稳定性，因为去掉量化后普通电平实际写入可能更频繁，
但不会绕过既有普通电平限频。

## 已知现象与范围

本地 DS 手柄的原神攀爬反馈是一拍一拍的 click，机身模拟路径则有“嗡一下”的感觉。
这个对比说明需要验证每拍的起振、结束和静默间隔，不能仅提高振幅。
原生 DS 触觉与串流收到的双通道 rumble 不一定是同一信号；本修改不声称恢复原生 HD 波形。

## 本次软件保证

- 包络按上一段保持的输入推进；重复包、相同时间戳和额外 ticker 不会改变时间积分。
- 瞬态收敛时先输出严格终态，再停止 ticker，避免小残差被最低振幅放大为持续底振。
- 起振按边沿安排，停止替换待执行电平；不会在收到停止后补播已结束的脉冲。
- 移除 60ms 观察窗口。机身的起停边沿绕过普通电平的 250ms 冷却，持续电平替换仍受限。
- 手柄始终保留全部 HOST 信号；点击能力位不再触发 25% 高频让渡。

这不保证零物理延迟：主线程调度、通信延迟及已阻塞的 Binder 无法被抢占。
如果 worker 尚未执行起振就收到停止，过期脉冲会被丢弃，不排队补播。
原语支持只记录能力；本次没有把每个 rumble 起振自动映射为 PRIMITIVE_CLICK。

## 真机比较（待执行）

保持同一攀爬路线、帧率、机身强度和握持方式，关闭音频派生触觉及触摸反馈干扰。
分别比较本地 DS、串流纯手柄、串流仅机身、协同模式，记录系统版本、机型、连接方式
及 `Device haptics tier` 日志。不要把测试得到的主观强度当作线性振幅等价。

1. 连续攀爬十步：每拍能否分清，拍间是否安静；立即停止攀爬，是否还有底振。
2. 持续低频振动后静止：机身补偿最终必须归零；高频持续的少量补偿仍是当前策略。
3. 连续快速起停及长时间攀爬：检查 vendor 服务无卡死、ANR 或堆积后的补播。
   250ms 保护保留在持续电平替换上，频繁起停的厂商兼容性需要单独验证。
4. 在支持的设备上，用独立测试程序对比直接 PRIMITIVE_CLICK、短 one-shot、完整游戏路径。
   点击原语必须先确认支持，并使用相同机身设置。这个 A/B 工具不包含在本次修改中。

若原语清脆但 one-shot 发闷，后续评估独立的点击补偿后端；若直接播放正常但整条路径
发闷，继续检查调度。需要同步采集 HOST 两通道及最终 vibrate/cancel 时间，才能区分
输入本来就是宽脉冲还是输出将其拉长。采集应使用临时诊断构建，避免长期逐包日志开销。
