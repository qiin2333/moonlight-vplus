# Moonlight V+ 翻译与术语说明（暂定）

本文记录 Moonlight V+ 当前的翻译边界，供维护者、贡献者和 AI 开发工具使用。

这些规则是当前协作约定，不是永久不变的语言规范。产品名称、固定配置名、技术标识和部分刻意保留的混合语言文案，未来都可以经过讨论后调整；但不要把这种调整混入普通翻译、补齐语言或文案清理 PR。若明确需要修改本文列出的特殊内容，请提交独立 PR，单独说明修改理由、影响范围和各语言的处理方式。

Moonlight V+ 不只追求字面上的统一。部分大小写、混合语言、命名方式和略带玩笑或彩蛋感的文本是项目风格的一部分。AI 很容易把这些内容判断为“不自然”“未翻译”或“拼写错误”，随后自动改成更标准但更普通的文案，最终丢失原有辨识度和娱乐性。没有明确的人类决策时，应优先保留，而不是主动纠正。

## 基本原则

- 翻译用户需要理解的标题、说明、错误提示、操作按钮和无障碍描述。
- 不翻译作为身份、协议、配置、存储或模板组成部分的文本。
- 不以“翻译覆盖率”“所有文字必须是目标语言”为理由强行改写固定名称。
- 不因为某个词看起来像占位符、临时文案或英文残留，就推断它应当翻译。
- 不同语言允许保留技术词和产品名；中英文混排本身不是缺陷。
- 无法确认文本性质时，保留默认语言回退，并在 PR 中提出问题，不要猜测。

## 固定名称与项目命名

下列名称默认保持原样。可以翻译它们周围的说明文字，但不要翻译、改写、重新分词或统一大小写。

| 固定文本 | 说明 |
| --- | --- |
| `Moonlight V+` | 客户端名称 |
| `Moonlight` | 上游项目和协议生态名称 |
| `Foundation Sunshine` | 主机端项目名称 |
| `Sunshine` | 主机端名称；不要与 Foundation Sunshine、Sunshine Base 相互替换 |
| `Sunshine Base` | 已有功能或兼容性描述使用的名称 |
| `Crown` | 屏幕按键、触控和振动反馈配置体系名称；周围的“管理、配置、市场”等普通词可以翻译 |
| `EasyTier` | 网络组件名称 |
| `VoidLink` | iOS 客户端名称 |
| `ZakoVDD` | 虚拟显示驱动名称 |
| `Moonlight PC` | 生态项目显示名 |
| `Moonlight macOS Enhanced` | 生态项目显示名 |
| `new DianLao ()` | 刻意保留的页面名称；大小写、空格和括号都是名称的一部分 |
| `Default` | 当它是配置、实例、预设或选项的正式显示名时保持原样 |

`Default` 需要按语境判断。下面两种情况不同：

- 配置名称是 `Default`：保持 `Default`。
- “恢复默认值”“默认端口”“默认情况下”等普通说明：应当自然翻译。

同理，`Crown` 需要保留，但 “Manage Crown profiles” 中的 “Manage” 和 “profiles” 可以翻译。

## 技术标识与协议名称

下列文本通常保持原样。列表不是穷举；新出现的协议名、编码名、字段名和硬件能力缩写应按相同原则处理。

### 视频、显示与音频

- `HDR`、`SDR`、`HDR10`、`HDR10+`、`HLG`、`PQ`
- `Dolby Vision`
- `H.264`、`H.265`、`HEVC`、`AV1`
- `P010`、`EDID`、`VRR`
- `PCM`、`Opus`、`AC3`、`E-AC3`、`Atmos`

### 网络、系统与设备

- `PC`、`root`
- `Android`、`Android TV`、`iOS`、`HarmonyOS NEXT`
- `Windows`、`Linux`、`macOS`
- `GeForce Experience`、`GFE`、`NVIDIA SHIELD Android TV`
- `USB`、`USB/IP`、`IPv4`、`IPv6`、`MAC`
- `HTTP`、`HTTPS`、`TCP`、`UDP`、`NAT`、`VPN`
- `QR`、`PIN`、`VID/PID`

### 性能、能力与算法缩写

- `FPS`、`Rx`、`Rd`、`FG`、`RTT`
- `VDD`、`ABR`
- `AEC`、`AGC`、`NS`

技术词周围的语法可以按目标语言调整，例如增加介词、连字符或空格，但技术词自身的字母、数字和大小写应保留。

## 按键与输入名称

当文本代表物理键、协议键位或存储值时，保持原样：

- `A/B/X/Y`、`L1/R1`、`L2/R2`、`L3/R3`
- `Start`、`Select`、`Guide`
- `Esc`、`Tab`、`Enter`、`Shift`、`Ctrl`、`Alt`、`Win`
- `BUTTON_A`、`KEYCODE_*`、`0x` 开头的键码

如果同一个词只是普通界面动作，则可以翻译。例如菜单中的“确认”“返回”“隐藏”应使用目标语言；显示某个真实键位时则保留键名。

## 单位

下列单位和项目约定的数值后缀保持原样：

- `ms`、`s`
- `Mbps`、`kbps`
- `KB/s`、`MB/s`
- `dB`
- `nits`
- `pixels`
- `frames`
- `FPS`、`Hz`、`%`

不要为了语言自然度自行替换成当地缩写，也不要仅因为显示结果相同，就让无关设置复用一个带有具体功能名称的资源。例如帧生成阈值不能引用“悬浮球自动隐藏延迟”的 `ms` 资源。

单位策略如果需要改变，应在独立 PR 中统一讨论，而不是只修改某一种语言或某一个页面。

## 格式参数、模板与持久化内容

下列内容属于程序结构，不是翻译文本，必须逐字保留：

### Android 格式参数

- `%s`、`%d`、`%f`
- `%1$s`、`%2$d`
- `%1$.2f`、`%.1f%%`

翻译可以调整带编号参数的顺序，但不能增删参数、改变类型或移除位置编号。

### Crown 性能模板

- `##Bandwidth##`
- `##Host Latency##`
- `##Net Latency##`
- `##Decode Time##`
- `##FPS##`
- `##Drop Rate##`
- `##Render Latency##`
- `HH:MM:SS`

模板周围的显示标签可以翻译，占位符本身不能翻译。兼容旧配置时，应增加明确的读取别名，不能批量重写用户已经保存的 Crown 内容。

`perf_decoder`、`perf_hdr_format`、`perf_resolution`、`perf_fps`、`perf_rx_fps`、`perf_rd_fps`、`perf_fg_fps`、`perf_frame_loss`、`perf_network_rtt`、`perf_host_latency`、`perf_decode_time`、`perf_bandwidth` 和 `perf_render_latency` 当前用于性能模板的数据键，不是界面标签。新语言不得为这些键增加本地化值，也不得为了本地化后的键增加新的运行时别名。

`PerformanceTemplateTokens` 只承担已发布旧配置的读取兼容。目前其中的中文别名用于识别旧版硬编码中文模板，以及用户导入、共享或继续使用的中文 Crown 配置；`Drop Rate` 和 `Net Latency` 是旧英文占位符别名。普通翻译 PR 不应扩展该兼容表。只有某个本地化标识确实进入过正式版本并被持久化后，才应在独立兼容性修改中增加别名并补充测试。

### 其他程序内容

- `\n`、`\'` 和必要的 XML 转义
- Preference key、action ID、枚举值、数据库列名
- JSON、TOML 和协议字段名
- URL、域名、文件名和扩展名（例如 `.mdat`）
- 服务端返回的原始字段、日志标签和序列化内容

不要为了消除硬编码警告，把协议值、日志或存储标识当作界面文案资源化。

## 可以正常翻译的内容

以下内容通常应按目标语言自然表达：

- 页面标题、分类名称和设置摘要
- 错误原因、操作提示和风险说明
- 普通按钮和菜单动作
- 无障碍描述
- 状态说明和诊断解释
- 固定名称周围的普通语句

示例：

| 原文 | 处理 |
| --- | --- |
| `Update Sunshine to continue` | 翻译句子，保留 `Sunshine` |
| `Dolby Vision requires HEVC` | 翻译语句，保留 `Dolby Vision` 和 `HEVC` |
| `Reset to default` | 自然翻译，因为这里的 default 是普通含义 |
| `Configuration: Default` | 翻译 “Configuration”，保留配置名 `Default` |
| `Manage Crown profiles` | 翻译动作和普通名词，保留 `Crown` |
| `new DianLao ()` | 完整保持原样 |

## AI 开发与审查要求

使用 AI 新增、补齐或审查翻译时，应把本文作为保护清单，而不是把默认语言文本全部交给模型自由改写。

1. 先区分普通界面文案、固定名称、技术标识、单位、模板和存储值。
2. 对固定文本做逐字比对，不接受模型自动“自然化”、改大小写或修正所谓拼写错误。
3. 对格式参数和模板占位符比较集合与类型，不只检查 XML 是否能够编译。
4. 不为了让每种语言的键数相等，复制错误翻译或改写不可翻译内容。
5. 不把一个功能专用资源复用到另一个无关功能，即使当前显示内容相同。
6. 对 `AV1`、`Dolby Vision` 等拼写检查误报，只做字符串级精确屏蔽，不全局关闭检查。
7. AI 无法确认意图时，应保留原文并在 PR 中列出疑问，不能自行决定项目命名。
8. 翻译 PR 不顺带整理代码、重命名功能、改变配置含义或重写用户数据。

## 修改特殊内容的独立 PR

本文是暂定约定，特殊内容并非永远不能改。如果维护者明确希望修改固定名称、技术词、单位或项目风格，应提交独立 PR，不要夹在普通翻译更新中。

独立 PR 至少应说明：

- 修改对象及其当前值
- 建议的新值
- 修改理由和用户收益
- 是否影响配置文件、备份、协议、模板或已有用户数据
- 所有支持语言如何处理
- 修改前后的界面示例；涉及短控件时提供小屏、横屏或电视布局检查
- 是否需要兼容旧名称或迁移已有配置
- 对本文保护清单的对应更新

这样可以让命名变化得到独立审查，也能防止 AI 在大批量翻译时顺手抹掉项目刻意保留的趣味、个性和历史痕迹。

## 提交前检查

- 新增资源在目标语言中有明确翻译或有意回退默认语言。
- 每种语言的格式参数与默认资源一致。
- 固定名称、技术标识、单位和模板占位符保持原样。
- XML 中的转义、换行、首尾空格和引号符合 Android 资源语法。
- 俄语、德语等长文本在窄屏控件中没有裁切或重叠。
- 希伯来语等 RTL 语言的标点、数字、方向和布局经过检查。
- 简繁中文、日语和韩语没有为了“更像英文”而保留不必要的空格。
- 至少运行资源处理、相关单元测试和 lint；涉及布局时补充实际界面检查。
